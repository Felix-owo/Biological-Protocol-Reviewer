# Biological Protocol Reviewer v1.5.0

Release date: 2026-07-11

v1.5.0 is a minor release because it intentionally changes the default
deliverable and several machine-readable contracts. It does not silently treat
proposed corrections as an implemented SOP.

## Runtime profiles

- `protocol_gate` is the default. It produces `Review_Report.md` and does not
  rewrite the protocol.
- `protocol_full` runs the same readiness gate, then produces
  `Revised_Protocol.md` only when the user explicitly requests an SOP rewrite.
- `delta_review` loads changed protocol sections, prior open findings, and
  affected modules without re-scoring untouched content.

Evidence, safety, traceability, and readiness standards are identical across
profiles.

## Contract migrations

| Before v1.5.0 | v1.5.0 requirement |
|---|---|
| Readiness could appear on a 0-100 scale. | Use a numeric 0-10 score; Level 0-3 must match the rubric range. |
| Operator burden could use `medium`. | Use `low`, `moderate`, or `high`. |
| Claim-readout handoffs had no version field. | Add `contract_version: "1.0.0"`. |
| Handoff root/items could drift or accept arbitrary extensions. | Root and item fields are sealed; extensions are limited to the two reviewer namespaces. |
| Source IDs could repeat. | `source_ids` must be non-empty, substantive, and unique. |
| The issue schema used a relative pseudo-shared ID. | Use `urn:biological-protocol-reviewer:schema:issue:1.0.0`. |

The shared handoff contract ID is
`urn:felix-research-codex:contract:claim-readout-handoff:1.0.0`.

## Validation changes

- Package-only validation is self-contained and works after the skill is copied
  to an arbitrary cache directory name.
- Release metadata checks run through explicit `--mode release`.
- Completed YAML Protocol Passports require PyYAML; without it, strict mode
  fails closed. `--allow-template` accepts only content exactly matching the
  bundled template.
- Markdown validation requires an explicit runtime profile. Strict-content checks
  are the default; `--lenient-content` is limited to legacy non-decision drafts
  and emits `decision_eligible: false` in JSON.
- Behavioral benchmark scoring links every expected concept and severity floor to
  a complete reasoned finding, so a generic finding plus a global keyword list
  cannot pass.
- The structured linter now supports local `$defs` references, `const`,
  `uniqueItems`, profile conditionals, score-to-maturity consistency, and delta
  finding-set invariants.
- Runtime-profile reference-file and character budgets are versioned in
  `references/skill_manifest.json` and cross-checked against the profile guide.
- Installability validation recursively resolves local JSON Schema `$ref`
  dependencies and fails before runtime if any referenced schema is absent.

## Upgrade and verify

```bash
git checkout v1.5.0
python3 -m pip install -r requirements-dev.txt
python3 biological-protocol-reviewer/scripts/check_installable_skill.py --skill-dir biological-protocol-reviewer
python3 biological-protocol-reviewer/scripts/check_version_consistency.py --mode release --repo-root .
python3 biological-protocol-reviewer/scripts/run_regression_fixtures.py
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python3 -m pytest -q
python3 tools/score_protocol_benchmark.py --benchmark-root benchmarks/v1.0
```

Existing saved handoffs must be migrated before validation. Historical release
records and v1.4.2 benchmark bookkeeping remain unchanged.

## Benchmark status

Deterministic contract and adversarial tests are included. No real model-output
files are bundled yet, so `benchmarks/results/v1.5.0/benchmark_summary.json`
keeps `model_outputs_scored` set to `false`, with no mean score or pass-rate
claim.
