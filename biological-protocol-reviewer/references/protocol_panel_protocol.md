# Protocol Panel Protocol

Use after module routing and evidence benchmarking, before final readiness score
and SOP rewrite. The goal is to prevent a single SOP-writing voice from missing
execution, interpretation, statistics, data, or governance failure modes.

## Required panel passes

| Panel role | Primary question | Output |
|---|---|---|
| Core-facility operator | Can a trained operator execute this without undocumented local habit? | Execution blockers, resource identity gaps, operator burden. |
| Domain PI / method expert | Does the protocol readout support the biological or technical conclusion? | Method-specific controls, interpretability risks, local validation needs. |
| Statistics and data reviewer | Are experimental unit, replication, randomization/blinding, batch, metadata, and analysis valid? | Design and data-analysis blockers. |
| Safety/governance reviewer | Is the procedure within compliant institutional execution and correctly bounded? | Approval, training, PPE, biosafety, animal/human/material governance findings. |
| Devil's Advocate | How could the protocol produce a convincing but wrong result? | False-positive, false-negative, contamination, batch, threshold, and audit loopholes. |
| SOP synthesizer | What is the smallest SOP package that is executable, auditable, and not overburdened? | Readiness score, Level 0-3 gate, issue priority, SOP rewrite priorities. |

## Rules

- Each panel pass must name the threatened readout, failure mode, and minimum
  resolution.
- The SOP synthesizer may integrate findings but must not delete unresolved
  Critical/Major concerns raised by other panel roles.
- If panel roles disagree, preserve the disagreement and resolve by readout
  risk, safety/governance risk, source authority, and local validation status.
- Use the panel only to strengthen protocol-readiness judgment; do not delegate
  SOP authorship or safety decisions to external companion skills.
